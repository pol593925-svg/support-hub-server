# Remote assistance, protocol 2 / Support Hub 3.44.1

An authenticated admin starts assistance from the employee's screen viewer. Both computers must run 3.44.1 or later. The employee sees In work, the admin name, a Stop button, and Ctrl+Alt+F12. No input blocking or confirmation dialog is introduced. Sessions end after ten minutes, disconnect, logout, renderer crash, or employee stop.

The primary display is enumerated once with thumbnails disabled and captured by one bounded MediaStream. WebRTC sends video directly where connectivity permits (8/12/15 FPS, 0.65/1.5/2.5 Mbit/s quality presets). If direct connectivity fails, a canvas asynchronously encodes binary JPEGs at bounded size and rate. Only one frame is in flight; its acknowledgement is sent after viewer decode. No JPEG/base64 capture or desktop enumeration runs per frame on the main process. Mouse positions use a separate volatile channel and are coalesced locally; clicks, drag button transitions and keys remain ordered.

The viewer opens fullscreen and restores its previous state on exit. Keyboard input is active only while the screen area is focused. Printable characters use Unicode SendInput (Russian/English independent of layout); navigation and shortcuts use an allowlist of virtual key codes. Ctrl+V and the Paste button send only the explicitly requested clipboard text, up to 20,000 characters. Images/files and automatic clipboard synchronization are not implemented. Opening links permits only HTTP/HTTPS.

The fixed C# input loop compiles once inside a hidden PowerShell process. Network strings are JSON data, never shell code. Mouse buttons release on blur, disconnect, stop, EOF and an idle watchdog. The helper is DPI-aware; the viewer maps letterboxing to normalized primary-display coordinates. Windows secure/UAC desktops and OS-reserved local shortcuts remain outside this feature.

Server binds all frames, signaling and input to both socket IDs and a random session ID. Only current admins can initiate; authentication is rechecked during active traffic. Inputs, signaling, JPEG size and rate are bounded; audit records are mandatory before the session begins.

Validation: assistance-integration.cjs (real Socket.IO), assistance-native.test.cjs (mocked OS calls), assistance-input.test.cjs (compiled C# with Win32 replaced by stubs), assistance-helper-check.cjs (real compile/probe only), assistance-capture-test.cjs (real local Windows capture, no images saved/transmitted), assistance-electron-test.cjs (two Electron renderers, real WebRTC plus forced JPEG fallback, synthetic screen and mocked native input). Tests never control a real employee's computer.
